# codeloom benchmarks

Measured numbers only — no fabricated results. Every figure below was produced
by actually running the tool (reproduce commands included; `bench/RESULTS.md`
carries the static-replay table regenerated by `python3 bench/run_bench.py`).

## Reproducibility pledge

Every number in this file was produced by the script named beside it — run
that command to reproduce it. Nothing here is copied from another project's
published benchmark or estimated by hand: the scripts live in `benchmarks/`
(and `bench/` for the static-replay table), run offline with no dependencies,
and each section names its repo, measurement date, and tokenizer. If a number
does not reproduce on your machine, file an issue with your output and the
command you ran. Companion tables that this file links to —
the 98.8% token-efficiency run, the 99.9% memory-eval fastapi run, and the
sealed 1–3/10 retrieval run — carry their own commands in
[`benchmarks/README.md`](benchmarks/README.md).

**Verification status — what this is NOT:** these are **self-published
measurements** made by the project on its own code. **No independent
third-party benchmark of codeloom exists yet.** Anyone is welcome to re-run
the commands below and publish their own numbers — including numbers that
disagree with ours.

## Dogfood head-to-head (measured 2026-08-23, pallets/flask, same-session)

Honest check: codeloom 0.79.0 vs plain grep+read on the same 83-file repo in
the same session, counting terminal payloads. **codeloom used MORE total
tokens (+14.5%) and wall time (+2.6x)** — the CLI returns full payloads,
which is the honest cost of terminal transport. It won on evidence:

- `--impact` — blast radius in **0.23s**: 5 direct + 33 transitive dependents
  (grep+read cannot produce a blast radius at all)
- `--task` ranked the exact modules the change needed
- `--checkpoint`/`--checkpoint-restore` reproduced the exact edit diff
- graph-neighbor memory retrieval (`--memory`) worked

**Scope note:** the token-efficiency claims (98.8%, 43–54×) apply to big-repo
chains-of-calls vs grep+read baselines, **not** to small-repo single-agent
sessions — both numbers are true; the scope is the difference.

Reproduce (deterministic, zero-LLM, any repo — never touches the target's
state; runs codeloom on a scratch clone):
`python3 benchmarks/dogfood_bench.py --repo <r> --task '<t>' [--expect f1,f2] [--runs N] [--json]`

## Static-replay retrieval (bench/RESULTS.md, measured 2026-08-22, fastapi)

20 architecture questions, one `--answer` call vs scripted grep+read:
codeloom 20/20 rows, 1 call + 149–624 bytes each vs 2–9 calls + 12–265 KB.
Scripted policy — not live-agent tokens. Reproduce:
`python3 bench/run_bench.py /tmp/bench-fastapi`

## Compaction recovery (measured 2026-08-22, fastapi)

After a compaction, re-deriving context: bare grep-and-read chain (33 calls,
84.5 KB) vs `--resume` + `--query-memory` (2 calls, 3.8 KB). **95.4% fewer
tokens.** Reproduce: `python3 benchmarks/compaction_recovery.py --repo /tmp/bench-fastapi`

## vs code-review-graph (measured 2026-08-22, fastapi, same symbols)

Symbol retrieval: codeloom 9–10 tokens vs crg 428–485 (43–54× fewer) —
`benchmarks/vs_crg.py` (table below in `benchmarks/README.md`).
Setup: codeloom 1 file / 3.23s cold, 0.13s warm with index vs crg pip 75
packages (8.6s) / 42.6MB graph / daemon 16.3MB RSS / embeddings extra. MCP:
codeloom 82 tools + NL router vs crg 30 tools no router (both counted live).
Loss rows: task brief 1,625 vs their 161 tokens (theirs is a pointer card;
ours embeds the code); crg first query 0.18s after build vs codeloom `--answer`
~3.2s (codeloom's fast path is `--get-symbol` after `--index`, 0.13s).
Reproduce: `CRG_BIN=... python3 benchmarks/vs_crg.py --repo ... --symbols Body,Cookie,File,Header`

## Linux kernel (Rust walk+map, measured this session)

Cloned `torvalds/linux` (shallow, ~2 GB) and ran the Rust core (`codeloom_rs`).
This is the **Rust walk+map** measurement (67,306 files / 5.66M symbols /
~11–13s). It is distinct from the **C-engine full graph** measurement (64,814
files / 3.2M symbols / 408k edges / ~89–113s — see
[`benchmarks/hardware-scaling.md`](benchmarks/hardware-scaling.md)):

| Metric | Result |
|---|---|
| Code files | **67,306** |
| Symbols extracted | **5,663,390** |
| Wall time (walk + map) | **~11–13 s** |

The kernel clone was a benchmark artifact and removed after measuring. Reproduce
with:

```bash
git clone --depth 1 https://github.com/torvalds/linux.git
./codeloom_rs map linux      # ~12s, 67,306 files, 5.6M symbols
./codeloom_rs files linux | wc -l
```

## Semantic search (subword-hash, zero-dep)

| Query | Top match | Similarity |
|---|---|---|
| `engin` (typo) | `Engine` | 0.72 |
| `getengine` (camel split) | `Engine` | 0.70 |
| `retrey` (typo) | `retry` | 0.43 |

Reproduce (no index needed; a 2-file fixture is enough — a larger repo will
return the same top match for these queries, and the exact similarity scores
above are what this fixture yields):

```bash
mkdir -p /tmp/embed-min && printf 'class Engine:\n    def run(self):\n        pass\n' > /tmp/embed-min/engine.py \
  && printf 'def retry(fn, times=3):\n    return fn\n' > /tmp/embed-min/utils.py
python3 codeloom.py --embed-search engin /tmp/embed-min   # Engine  (sim 0.719)
python3 codeloom.py --embed-search getengine /tmp/embed-min  # Engine  (sim 0.698)
python3 codeloom.py --embed-search retrey /tmp/embed-min  # retry   (sim 0.434)
```

## Multi-repo / cross-service

`codeloom_rs cross <a> <b>` detects a symbol defined in repo A called from repo B:

```
xrepo_b -> verify_token (defined in xrepo_a)
xrepo_b -> get_user (defined in xrepo_a)
```

## Honest scope

- The kernel benchmarks are **walk + symbol extraction** (Rust) and **full graph
  + symbol index** (C engine), not a full 100-language semantic deep-index
  (that's the ongoing tree-sitter work — 50 dispatched / 46 fixture-proven today).
- The `--embed-search` numbers use the zero-dependency subword hash. When a local
  ggml model is present (`CODELOOM_GGML_BIN`/`CODELOOM_GGML_MODEL`), it upgrades to
  real neural embeddings automatically.
