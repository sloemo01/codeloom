codeloom — the context engine for coding agents

An honest, reproducible engineering report. Not peer-reviewed; a verifiable account of architecture, measured results, and deliberate limits.

Abstract

Codeloom optimizes the metric that decides agent adoption: how efficiently an agent turns a task into a correct change. Where most code-intelligence tools compete on graph depth (nodes and edges), codeloom competes on agent cognition — serving the minimal high-signal context packet and persisting the agent's own work across context compaction.

1. Thesis

An agent's repo knowledge and its work-in-progress understanding survive a context compaction only if written to disk. Codeloom provides the write surfaces (--decide/--reject/--hypothesis, --mark-seen, --checkpoint, --working-state) and reconstructs the agent's state after any wipe. It stores actions and decisions, not the model's internal reasoning (which cannot be recorded).

2. Architecture

Five scanning paths, one interface:

EngineRoleDependency
Pure-Python (default)zero-dep walk + symbol + call graphnone
C core (--engine c)compile-once accelerator, auto-buildscc
Rust core (--engine rust)multi-threaded, auto-buildsrustc
codeloom_rsfull standalone Rust CLIrustc
engine_rs/real tree-sitter AST, languagescargo (optional)

The MCP layer (74 tools) wraps these behind a single entry point (codeloom_ask) that routes deterministically.

4. Honest limitations

  • 30 tree-sitter languages today (not 100+; the rest use the fast regex walker).
  • Neural embeddings require a user-supplied local ggml model (infrastructure wired; a bundled model would break the zero-dep single file).
  • The kernel benchmark is walk + symbol extraction, not full semantic deep-index.
  • No claim to "understand" code better than codebase-memory; the win is agent context efficiency and memory, not raw graph depth.
